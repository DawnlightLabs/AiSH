# AiSH v0.6.4

AiSH v0.6.4 replaces phrase-specific natural-language workarounds with a generic semantic planning and host-resolution pipeline.

## Planner reliability

- Introduced compact semantic plans for navigation, shell commands, filesystem actions, answers, and clarifications.
- Added resilient structured-output parsing for prompt echoes, wrappers, Markdown fences, trailing runtime text, legacy fields, multiple JSON objects, and malformed or truncated output.
- Added one bounded corrective retry with request-class-specific constraints.
- Added opt-in sanitized diagnostics covering model output, parser strategy, runtime arguments, exit status, and parse errors.
- Prevented internal schema and command-card terminology from leaking into normal user errors.

## Navigation and filesystem actions

- Resolves arbitrary existing directories from the current directory, home, known folders, relative paths, drive roots, and bounded filesystem searches.
- Preserves spaces, mixed case, Unicode, redirected Windows known folders, and platform-specific path behavior.
- Detects ambiguity and missing targets without inventing paths.
- Handles parent movement and uniquely grounded existing-directory requests directly in the host.
- Resolves create, delete, rename, move, and copy actions against verified filesystem entries before generating platform-safe commands.
- Adds post-command verification for filesystem changes while keeping mutation and deletion approval-gated.

## Shell behavior and safety

- Uses syntax-based routing for literal commands and natural-language requests without command-name or folder-name catalogs.
- Keeps generated commands under host-side risk classification and approval.
- Rejects read-only substitutions for state-changing requests.
- Supports bounded multi-command plans that stop on failure.
- Reports successful commands that returned no output and failed commands that produced no output.
- Keeps failed-command recovery bounded and prevents recursive recovery.
- Adds host-grounded quantitative observations such as directory-size ranking and file or directory counts.

## Models and runtime

- Discovers compatible GGUF files from the managed models directory.
- Supports persisted model selection through `/model list`, `/model use`, and `/model status`.
- Uses declarative model profiles for structured output, prompt behavior, context size, output limits, and retry strategy.
- Detects managed llama.cpp runtime capabilities and enables automatic GPU offload with safe fitting where supported.
- Verifies that updates replace the executable and managed runtime files together.

## Shell experience

- Adds persisted `/theme` support with Dawnlight, Ocean, Forest, Ember, Violet, Mono, and Off themes.
- Resolves Windows known folders through the operating system rather than assuming fixed user-profile paths.
- Keeps corresponding Linux and macOS path, quoting, navigation, and command-generation behavior.

## Validation

- `cargo fmt --all -- --check`
- `cargo check -p aish-provider-shell --quiet`
- `cargo build -p aish-provider-shell --quiet`
- 104 provider tests
- 29 provider-shell tests

- 5,000-case literal and natural-language routing acceptance suite
- 380 real-model plans across Qwen2.5 Coder 1.5B Q4_K_M, Q5_K_M, Q6_K, and Q8_0
- 100% valid-plan rate, 0 incorrect actions, and 100% clarification quality across all four evaluated models

## Upgrade

Inside AiSH, run:

```text
/update
```

Or from PowerShell, Command Prompt, bash, or zsh:

```text
aish --update
```

Restart AiSH after the updater finishes.
